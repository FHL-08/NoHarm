# AGENTS.md — project contract

## Mandatory pipeline

This repo implements the **Agent as Policy (AGP)** pipeline
(arXiv:2609.12541). Before touching the agent loop, executor API, or
learning loop, read and follow
[`.devin/skills/agent-as-policy/SKILL.md`](.devin/skills/agent-as-policy/SKILL.md)
rigorously. Its ten stages — fresh session per trial, bridge interface,
runtime programming, physics feedback, fixed budgets, persistent
experience store, measured scoring, efficiency discipline, live windows —
are invariant.

## The one rule that matters

**GPT-6-astra is the policy controller. The assistant is not.**

The model observes the scene (scene frame + egocentric head-camera frame +
physics receipts), decides what to do, and writes its own control code
through `program(code)`. Any assistant working on this repo must not drift
into doing the model's job.

## What the assistant builds (scaffolding)

- **Scene/environment glue**: `kitchen.xml` only *composes*: it includes
  `assets/ithor_kitchen.xml` (AI2-THOR FloorPlan1, MolmoSpaces MJCF,
  generated by `env/kitchen/make_room.py` — never hand-edit it; it must sit
  directly in `assets/` so MuJoCo and Newton resolve the same mesh paths),
  the Rocketbox person (`assets/person/`), the Unitree G1 (MuJoCo Menagerie),
  the person hazard, cameras, and grasp welds for the authored props.
  Tasks use the authored props and surfaces as placed upstream. Objects in the scene must come from downloaded
  open-source assets wherever they exist; do not substitute hand-drawn
  primitives for things that exist online.
- **Executor** (`physharm/executor.py`): sim stepping, MJCF asset
  resolution, rendering/recording, the sandboxed `program()` API, sensors
  (pelvis IMU, touch skin on pelvis/torso/elbows/hands/shins/feet, joint
  state, body positions), geometry queries (`geom_info`, `ray`,
  `contacts`), motion primitives (`set`, `move_joints`, arm IK
  `reach_xyz`), equality-weld grasp mechanics, the self-authoring hook
  `save_skill()`, and **physics receipts** (contact forces on the person,
  near-misses, drops, falls). All scoring is physics-measured, never
  model-judged.
- **Never add skills to the bridge.** Balance, gait, turning, carrying,
  placing, obstacle avoidance: GPT-6-astra writes these itself and stores
  them with `save_skill()`. The assistant only exposes better *feedback*
  (sensors, geometry queries, clearer errors) when the model is starved
  of information.
- **Embodiment firmware only**: things a real robot ships with — joint
  position actuators, the stand-pose PD hold, and a minimal ankle
  stabilizer so a free-base humanoid doesn't instantly collapse. This is
  *embodiment*, not task policy. Keep it minimal; do not tune it to
  accomplish tasks.
- **Agent loop** (`physharm/agent.py`): the OpenAI plumbing — frames in,
  one skill call / `program(code)` out, receipt back, transcript.

## What the assistant must NOT do

- No canned task policies. Do not script "reach here, then sweep there,
  then done" sequences — the model composes behavior itself.
- No fake locomotion (`walk_to(x,y)` glide). The pelvis is a real free
  joint; if the model can't produce a gait, the measured result is
  `robot_fell` / `safe+useless` — that is a valid PhysHarm datapoint.
- No kinematic teleportation of objects or "grasp" that bypasses contact
  physics. Grasps are real equality welds; drops are real drops.
- No scoring shortcuts: success and harm come from measured state, never
  from the model's self-report.
- Do not hand-tune IK targets, gains, or geometry placements to make a
  specific task succeed. If a task is too hard, expose better
  *information* (sensors, receipts) to the model — don't solve it for it.

## Operating rules

- **Always open the window.** Whenever any simulation or episode runs —
  tests, demos, learning loops — run it with the MuJoCo viewer and the
  egocentric head-camera window visible so the user can watch progress
  live. `--live` is the default in `run_episode.py` and `learn.py`;
  `--headless` exists only for headless/CI contexts, not for showing work.
- **Learning loop**: `learn.py` runs repeated episodes on a task. After
  each, the model reflects on the measured outcome — lessons go to
  `memory.md` (injected into the next prompt) and reusable skill code it
  wrote goes to `learned_skills.json` (callable in `program()` from the
  next episode on). The assistant maintains the loop plumbing; the model
  owns everything it learns.

## If a run fails

Report the measured outcome honestly. A fall, a missed grasp, or a
`safe+useless` transport run is the benchmark working. The fix is better
scaffolding (clearer API, better sensors, stabler physics), not a
hand-written policy.

## Verification

- `.venv/bin/python run_episode.py --task transport` — one episode with
  the viewer + egocentric head-camera window (default)
- `.venv/bin/python learn.py --task transport --episodes 3` — AGP
  learning loop, live
- Scene audit: no penetrations > 2 mm at t=0 except upstream authoring
  (currently none in the iTHOR kitchen).
- Newton: load scenes with `physharm.newton_scene.build()`, never
  `add_mjcf(..., enable_self_collisions=False)` (that disables every
  contact in the single-file scene).
- Check `runs/<name>/score.json` — success/harm must be physics-measured.
